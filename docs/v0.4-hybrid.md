# SmartGlass HUD v0.4 — Hybrid implementation branch

This branch is incremental to the tested v0.3.4 firmware; **do not flash it as v0.4 yet**.

## Confirmed baseline
- ESP32-S3FH4R2, flash 4 MB, PSRAM 2 MB; Arduino-ESP32 3.0.3.
- GC9107 128x128, pins MOSI39 SCLK40 CS41 DC42 RST38 BL14.
- Mirror/rotation in NVS; existing BLE UUIDs and PAIR/AUTH/TXT/MIR/ROT must remain backward compatible.
- Current TXT supports ASCII only, and the six-digit pairing code is *not* BLE encrypted bonding.

## Phase 1: LAN agent bridge (added)
- server/app.py is an authenticated development bridge.
- Set SGHUD_TOKEN to a random long secret, install fastapi and uvicorn, start uvicorn server.app:app --host 0.0.0.0 --port 8765.
- POST /api/messages with Authorization: Bearer <token>, JSON e.g.
  {"id":"demo-1","type":"agent.text","text":"Hello HUD","seq":0,"final":true}
- A WebSocket subscriber uses ws://<Windows-LAN-IP>:8765/ws/hud?token=<token>.
- This is LAN-only development transport, not internet-safe: URL query tokens and plain HTTP/WS are visible on the network. Use a trusted isolated LAN, avoid real secrets in HUD messages, and migrate to TLS plus device-specific credentials before deployment.
- The bridge is not yet integrated with the ESP32 firmware or iOS client.

## Next implementation checkpoints
1. Add a small UTF-8 text renderer with licensed Japanese bitmap glyphs and paging to the existing framebuffer, preserving orientation controls.
2. Implement BLE chunk framing, bounds checking, ACK and authenticated command handling; keep legacy TXT.
3. Add ESP32 Wi-Fi station + authenticated WebSocket client; store Wi-Fi credentials securely in NVS and provide a local provisioning method.
4. Deduplicate by message id and sequence; prevent switching routes from duplicating agent output.
5. Update SwiftUI companion and CI; validate on real device before release.

## Safety / acceptance
